Player Stamping System Review & Situational Applicability Options

In RL-Sync, visual “stamps” (vermilion Hanko seals, gold/carry cartouches, and relationship plaques) give instant scouting context in live Rocket League lobbies and player dossiers. Right now, the SMURF and threat rules simultaneously over-flag normal opponents on playlists a user does not play and miss actual single-playlist fresh alt accounts.

◆ LIKELY ALT · 14G · 6W STREAK ◆ OFF-MODE PEAK · 2V2 GC II ◆ PARTY CARRY (+145 VS MATE) ◆ HIGHER MMR (+78 VS YOU) ◆ PRIME DUO (8–2) ◆ NOTE · FLIP-RESET ALT

Why False-Positive “Smurf” Stamps Happen

threatBadges.ts loops over every playlist returned by PsyNet—including Casual (0), Tournaments (34), Extra Modes (27–30), and unplayed core modes—and subtracts raw MMR against localPlayer.ranks[pid].mmr. Unplayed local modes sit at default/decayed 600–980 MMR, and 1v1 runs ~300–350 MMR lower than 2v2 for the same tier.

Why Real Fresh Smurfs Slip Through (0% Recall)

A brand-new Epic alt queuing only 2v2 (14 total games, 0 games in other modes) has no higher off-playlist rank, so cross-playlist subtraction never triggers. Meanwhile, PsyNet’s rlapi.Skill response already delivers TrueSkill Sigma (uncertainty), WinStreak, and MatchesPlayed—currently dropped at ingestion.

Defect 1 — Unengaged Local Playlists Cause Systematic False “SMURF” Stamps

In web/src/utils/threatBadges.ts, every playlist key on player.ranks is compared directly against localPlayer?.ranks?.[pid]?.mmr: 

for (const [pid, r] of Object.entries(player.ranks)) {
  if (pid === activeKey || !r || !r.mmr) continue;
  const localModeMmr = localPlayer?.ranks?.[pid]?.mmr || localActiveMmr || 1450;
  const diffVsYou = Math.round(r.mmr - localModeMmr);
  const diffVsOwnActive = playerActiveMmr > 0 ? Math.round(r.mmr - playerActiveMmr) : 999;
  if (diffVsYou >= 120 && diffVsOwnActive >= 80) { /* stamps SMURF */ }
}

When you do not engage in playlist pid, PsyNet either omits it or returns a decayed/uncalibrated base rating (600–980 MMR). Meanwhile, BuildRanksSnapshot in internal/playertrack/rank_helpers.go serializes all PsyNet skill buckets—including Casual (Playlist 0, where Champ/GC players routinely sit at 1650–2000 MMR), Competitive Tournaments (Playlist 34, inflated +120–220 MMR), and Extra Modes (27–30). Any normal opponent who plays Casual, Tournaments, Rumble, or a core mode you skip is falsely branded ◆ SMURF.

Defect 2 — Raw MMR Subtraction Fails Across Incompatible Playlist Scales (1v1 vs. 2v2/3v3)

Even inside Ranked Core Soccar, raw MMR numbers do not map 1:1 to skill tiers: Grand Champion I (Tier 19) begins near ~1435 MMR in 2v2/3v3, versus ~1090 MMR in 1v1—a ~345 MMR structural offset. A normal 1420 MMR 2v2 player sits around 1000–1030 MMR in 1v1. When queuing 1v1, r.mmr - playerActiveMmr is automatically +390 MMR, branding ordinary 1v1 opponents as smurfs whenever your own 2v2 MMR is unplayed or slightly lower.

Defect 3 — Semantic Conflation (“Off-Mode Veteran” vs. “True Alt”) & 0% Recall on Single-Mode Alts

The current detector conflates a 4,000-game veteran queuing a rusty secondary playlist with a fresh alt smurf. Worse: a brand-new Epic smurf playing only 2v2 (14 games played, 0 games in 1v1/3v3) has zero off-playlist entries, so the current SMURF detector completely misses them (0% recall on single-mode alts).

Defect 4 — High-Signal PsyNet Fields (Sigma, WinStreak, PlacementMatchesPlayed) Dropped at Ingestion

github.com/dank/rlapi.Skill already returns authoritative TrueSkill parameters on every live rank lookup: 

type Skill struct {
    Playlist               int     // 10, 11, 13, 27..30, 34
    Mu                     float64 // Raw TrueSkill mean
    Sigma                  float64 // ~8.33 fresh -> ~3.00 season soft-reset -> 2.50 settled floor
    Tier                   int     // 0..22
    Division               int     // 0..3
    MMR                    float64 // Skill rating
    WinStreak              int     // Active consecutive wins in playlist
    MatchesPlayed          int     // Current season games in playlist
    PlacementMatchesPlayed int     // 0..10 placement progress
}

FromSkill in rank_helpers.go currently discards Sigma, WinStreak, and PlacementMatchesPlayed, and threatBadges.ts ignores MatchesPlayed.

Defect 5 — Hardcoded 1515 / 1450 Fallbacks & diffVsOwnActive = 999 Bypass

When local rank data has not resolved yet, threatBadges.ts falls back to hardcoded 1515 (GC1) and 1450 MMR constants. And if an opponent is unranked/unfetched in the active mode (playerActiveMmr === 0), diffVsOwnActive defaults to 999, automatically bypassing the >= 80 guard.

Defect 6 — Hair-Trigger “HIGHER MMR” (+1 MMR Stamps ~50% of Normal Lobby Opponents)

HIGHER MMR (+X VS YOU) fires at diff > 0 (literally +1 MMR). Normal Rocket League matchmaking pairs players within ±25 MMR (~2.5 wins), causing ~50% of completely even opponents to carry a gold warning stamp and creating severe badge fatigue.

Defect 7 — Teammates Stamped as Red Threats & Dossier allLobby Party-Carry Bug

SMURF omits the isOpponent check, stamping your own solo-queue teammates with red threat seals (+X VS YOU). Separately, usePlayerDossierData.ts passes allLobby (both teams combined!) as opposingTeamPlayers, causing CARRYING (+X VS MATE) in Dossiers/Modals to compare an opponent against your team’s MMRs.

Defect 8 — 1-Game Relationship Hair-Triggers & Backend/Frontend Formula Split-Brain

After a single 0–1 loss to a random player, Go’s internal/storage/helpers.go stamps NEMESIS while TypeScript’s broadcastLabels.ts stamps ARCH-RIVAL. At 2–3 (40% WR), Go returns ARCH-RIVAL while TS returns NEMESIS. At 1–1 (50%, 2 games), Go falls through to FAVORABLE FOE.

Defect 9 — Role-Context Masking (tG >= oG Hides Active Opponent Danger)

Because relationship tags check if (tG >= oG) globally regardless of current team assignment, a regular you went 3–1 with as a teammate—but 0–3 against as an opponent—still displays SYNERGY ALLY even while lined up on the opposing team in a live match.

Defect 10 — Manual Scouting Tags & Notes Never Hydrate into Live Lobby Cards

LivePlayerCard.tsx renders player.tags and player.notes, and TypeScript’s LobbyPlayer interface declares them, but Go’s playertrack.LobbyPlayer struct omits both fields and never loads them from SQLite when a live match begins.

Option 1 — Playlist-Family & Engagement GatesFrontend Only

Partition playlists into strict families—Core Soccar (10, 11, 13) vs. Extra Modes (27–30)—and ban Casual (0) and Tournaments (34) from triggering cross-mode stamps in Ranked Soccar. Skip comparing against localPlayer.ranks[pid] unless both players have matches_played >= 15.

Pros: Zero backend changes; kills Casual, Tournament, and Rumble false positives immediately.
Cons: Still breaks on 1v1 ↔ 2v2 (~345 MMR gap), mislabels veterans as “SMURF”, and catches 0% of fresh single-mode alts.

Option 2 — Normalized Tier + “User Peak” BenchmarkSolves Unplayed Modes

Stop comparing opponent.ranks[off] against your.ranks[off]! Map Core Soccar ranks onto a normalized continuous tier index S(p, r) (accounting for 1v1’s ~+1.75 tier compression relative to 2v2/3v3) and require both conditions:

Δ_self = S_peak(Player) − S_active(Player) ≥ 2.0 tiers
Δ_vs_you = S_peak(Player) − max(S_active(You), S_peak(You)) ≥ 1.5 tiers
Pros: Immune to playlists you don’t play and 1v1 deflation; emits honest OFF-MODE PEAK instead of false SMURF.
Cons: Cannot detect genuine fresh alt accounts queuing a single playlist.

Option 3 — PsyNet TrueSkill Sigma + Volume + StreakCatches True Alts

Expose Sigma, WinStreak, and PlacementMatchesPlayed from rlapi.Skill. Rocket League’s server physics distinguish fresh accounts from season soft-resets: settled veterans sit at σ = 2.50, seasonal soft-resets add +0.50 (capping near σ ≈ 3.00), whereas brand-new accounts start at σ = 8.333 and stay σ >= 3.35 for ~15–25 games.

Tier ≥ 12 (Plat III+) AND LocalPlayerSettled AND:
(Sigma ≥ 3.35 ∧ AccountGames ≤ 35) OR (Sigma ≥ 2.75 ∧ AccountGames ≤ 45 ∧ WinStreak ≥ 4)
Pros: Catches single-playlist Epic smurfs using authoritative PsyNet data; safe on Day-1 season resets.
Cons: Adds 3 optional fields to schema/dto.yaml + schemagen.

Option 4 — Live Party & Box-Score CorroborationSituational Context

Evaluate stamps in context of party MMR spread and team alignment: raise PARTY CARRY to >= +100 MMR vs. their own teammate (fixing Dossier allLobby), flag mid-match reverse-boost carries (low-MMR high-Sigma party mate dominating score), and keep teammate cards strictly informational/positive rather than alarming red threat seals.

Pros: Aligns stamp tone with whether a player is helping you or threatening you; catches boosting duos.
Cons: Mid-game score corroboration only activates after kickoff/early play (~90s elapsed).

Option 5 — Recommended Unified Multi-Signal Architecture (Options 2 + 3 + 4 + H2H & Live Tags) ★ Recommended

Separates conflated concepts into clean, high-trust signals so every stamp means exactly what it says—and no stamp ever fires simply because you don’t play a given playlist.
